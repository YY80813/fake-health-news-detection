# Gradio is deliberately NOT pinned here - the `sdk_version: 6.26.0` line in
# this folder's README.md frontmatter is what tells Hugging Face which
# Gradio to install for a Gradio-SDK Space, and that applies regardless of
# hardware tier. Pinning a *different* Gradio version here as well (as an
# earlier version of this file did, at 3.50.2) caused a hard pip dependency
# conflict during the build ("ResolutionImpossible") against that
# SDK-provided version.
#
# torch IS explicitly listed below (via PyTorch's CPU wheel index), which
# was NOT needed while this Space ran on free ZeroGPU hardware - ZeroGPU
# pre-bakes its own CUDA-enabled torch into every ZeroGPU Space's container
# regardless of requirements.txt, so listing it here would have been
# redundant (and risked a conflicting version). CPU Upgrade hardware is a
# plain, general-purpose container with no such special provisioning, so
# without an explicit torch dependency here the app crashes at startup with
# `ModuleNotFoundError: No module named 'torch'` - exactly what happened the
# first time this Space was switched to CPU Upgrade. If this Space is ever
# moved back to a GPU/ZeroGPU tier, this explicit CPU-only torch install
# should be removed again, since it would conflict with that tier's own
# pre-installed CUDA torch.
--extra-index-url https://download.pytorch.org/whl/cpu
torch
#
# transformers is installed straight from GitHub's main branch rather than
# a normal PyPI version pin because of a temporary ecosystem-wide gap:
# huggingface_hub just had a 1.0 major release, Gradio 6.26.0 requires
# huggingface-hub>=1.16.0,<2.0, but every transformers release on PyPI so
# far (up to 4.57.6) still hard-caps huggingface-hub<1.0 - those two
# requirements can never both be satisfied together from released
# packages, which is exactly the "ResolutionImpossible" conflict this
# caused. The fix is already merged into transformers' unreleased code
# (main now requires huggingface-hub>=1.5.0,<2.0, which IS compatible with
# Gradio's requirement) but hasn't shipped as a stable PyPI release yet, so
# installing directly from the repo is the workaround until it does. Once
# a new transformers version is released on PyPI with that fixed
# constraint, this can be switched back to a normal "transformers>=X,<Y"
# line.
transformers @ git+https://github.com/huggingface/transformers.git
